# 김킷 스타일 에너지 게임 — 설계 문서

작성일: 2026-11-19 / 상태: 승인 대기

## 1. 의도와 이유
초등학생(전학년)이 게임을 하다가 에너지가 떨어지면 김킷 스타일 퀴즈를 풀어 에너지를 채우는 모바일 웹앱.
퀴즈를 "벌/장벽"이 아니라 "보상"처럼 느끼게 하는 것이 핵심 가치다. 게임과 문제 세트는 계속 추가될 수 있어야 한다.

## 2. 목표 / 비목표 / 안티목표
**목표**
- 모바일 세로 화면 웹앱, 설치 없이 브라우저에서 실행
- 게임 2종(점프맵, 무한의 계단), 이후 게임을 쉽게 추가할 수 있는 구조
- 문제 세트 선택(과목→세트→단원), 지금은 구구단만 탑재, 이후 JSON 파일로 영단어·분수 등 추가
- 김킷 스타일 퀴즈(색깔 4지선다, 즉각 피드백, 연속 정답 배율)
- 게임 종료 시 기록 표시, 최고 기록 기기 저장

**비목표 (이번 범위 아님)**
- 코인/상점/캐릭터 꾸미기 (정답으로 얻는 것은 에너지뿐)
- 멀티플레이, 계정, 서버, 랭킹
- 앱 안의 문제 업로드 화면 (문제는 JSON 파일을 폴더에 추가)
- 호스팅 설정 (정적 파일이라 나중에 GitHub Pages 등에 올리면 됨)

**안티목표 (기술적으로 동작해도 실패인 경우)**
- 퀴즈가 벌처럼 느껴짐(오답 시 큰 불이익, 지루한 대기)
- 손가락으로 조작 중 화면 확대·스크롤·선택이 튀어나옴
- 게임 중 프레임이 눈에 띄게 끊김

## 3. 제약
- 순수 JavaScript(ES modules) + HTML/CSS + Canvas, 빌드 도구 없음
- 세로 화면 전용(최대 폭 480px 중앙 정렬, 100dvh, safe-area 대응), 터치 우선(마우스·키보드도 보조로 동작)
- 효과음은 WebAudio로 합성(외부 음원 파일 없음), 진동은 지원 기기에서만
- 기록 저장: localStorage (접근 실패 시에도 동작)

## 4. 접근 방식 (고려한 것과 선택)
- **A. 순수 JS + Canvas (선택)**: 빌드 없음, 폴더 하나로 배포, 파일 경계가 분명해 에이전트 병렬 작업에 적합. 공통 코드는 뼈대에서 한 번만 만든다.
- B. Phaser 3: 물리·장면 관리 내장이나 퀴즈 UI는 어차피 HTML이라 과함.
- C. React+Vite+TS: 빌드 환경 필요, 게임은 Canvas라 이득 작음.

## 5. 핵심 규칙 (결정 사항)
### 에너지
- 최대 10. 게임 시작 시 가득 참.
- 점프맵: 점프 1회 = -1. 이단 점프(공중에서 새로 눌러 한 번 더)도 실제로 점프하면 -1. 가만히 있거나 이동만 할 때는 소모 없음. 에너지 최대 15. (변경: 초기 스펙의 "공중 재점프 불가"를 이단 점프로 대체)
- 무한의 계단: 계단 한 칸 오를 때마다 -1. 에너지 최대 20, 정답 충전량 ×2. 화면 전체를 좌우 절반으로 나눠 왼쪽 터치 = 왼쪽, 오른쪽 터치 = 오른쪽.
- 에너지 0에서 소모 행동을 하려 하면 게임이 일시정지되고 퀴즈 화면이 뜬다. (점프맵은 공중에서 끊지 않고 착지 시점에 뜬다.)
- 에너지가 가득 차지 않았을 때는 언제든 "미리 충전" 버튼으로 퀴즈를 풀 수 있다.
- 시간 경과로는 에너지가 닳지 않는다(쫓기는 느낌 방지).

### 퀴즈 (김킷 스타일)
- 문제 1개 + 색깔 큰 버튼 4개(빨/파/노/초), 터치 시 즉시 정오 표시와 효과음
- 정답 시 충전량 = 올림(기본 2 × 배율). 연속 정답 배율: 1~2연속 ×1(+2), 3~4연속 ×1.5(+3), 5연속 이상 ×2(+4). (기본 1이면 ×1.5와 ×2가 같은 값이 되어 기본 2로 정정)
- 게이지가 눈에 보이게 차오르는 연출. 에너지가 가득 차면 "계속하기" 버튼
- 오답: 정답을 잠깐(약 1.2초) 보여 주고 연속 기록만 끊김. 감점 없음. 찍기 방지로 오답 후 약 1초 입력 잠금
- 연속 2번 오답이면 오답 보기 1개를 지워 준다(좌절 방지)
- 보기는 문제 데이터의 distractors를 쓰고, 없으면 자동 생성(숫자는 근처 값, 단어는 같은 세트의 다른 정답)

### 하트
- 3개. 게임 시작 시 가득 참. 퀴즈로는 회복되지 않음. 0이 되면 게임 종료 → 기록 화면.

### 점프맵
- 세로로 무한히 올라가는 구조물(발판) 위를 뛰어 높이 올라간다. 점수 = 도달한 최고 높이(m).
- 조작: 하단 왼쪽 좌/우 터치패드, 하단 오른쪽 점프 버튼. 화면 상단에 현재 높이와 최고 높이, 하트, 에너지 표시.
- 화면 아래로 떨어지면 하트 -1 후 마지막으로 밟은 안전한 발판에서 되살아남.
- 함정(가시 등)에 닿으면 하트 -1, 약 1.5초 무적.
- 발판은 절차 생성: 너비는 좁음/중간/넓음을 섞고(높이 오를수록 좁은 비율 증가), 세로 간격은 한 번 점프 높이의 0.6~1.5배로 다양(10m 미만은 쉽게, 이후 약 40%는 이단 점프 필요), 가로 이동 폭은 높이에 따라 ±100→±160. 8m부터 좁은 벽돌 4~6개를 옆으로 이어 건너는 징검다리 구간, 6m부터 움직이는 발판, 10m부터 가시가 등장. 이단 점프는 낙하 복구·가로 이동·높은 간격용.
- 구간 기획(점프맵 요소 단계적 도입): 높이를 20m(800px) 구간으로 나누고 구간마다 주 기믹 1개(plain/moving/stones/spikes/crumble/ice/conveyor/wind)를 구간 번호 해시로 결정(같은 기믹 연속 금지, 무거운 기믹 다음은 50% 이상 plain, plain 약 30%). 해금 높이: 움직이는 발판 6m, 징검다리 8m, 가시 10m, 부서지는 발판 20m, 얼음 35m, 컨베이어 50m, 바람 70m. 주 기믹은 구간 발판의 약 절반, 그 외 위험은 낮은 기본값.
- 발판 요소: 스프링 점프대(10m~, 약 25m마다, 착지하면 자동으로 약 190px 튀어 오름, 에너지 소모 없음, 이단 점프 회복), 부서지는 발판(밟고 0.5초 뒤 사라짐), 얼음 발판(미끄러짐), 컨베이어(±70px/s), 바람 구간(±45px/s, 높이 250~400px 영역에서 가로로 밀림).
- 아이템/체크포인트: 에너지 아이템(12m~, 약 40m마다, +3) , 퀴즈 블록(❓, 25m~, 약 60m마다, 닿으면 퀴즈), 아이템은 6개 발판 안에 1개 이하. 50m마다 체크포인트(넓은 발판+깃발): 처음 닿으면 하트 +1(최대 3), 낙하 시 부활 지점 후보.
- 에너지가 0이 되어도 공중에서는 끊지 않고 점프를 마친 뒤 착지하는 순간 퀴즈 화면이 열린다(부활 후 착지 포함). 지상에서 점프를 눌러도 퀴즈가 열린다. 공중 점프 입력은 에너지 0이면 무시.

### 무한의 계단
- 실제 "무한의 계단" 차용: 빌딩 외벽 배경, 블록이 좌우 지그재그 계단처럼 이어짐.
- 조작: 하단 좌/우 버튼만. 다음 블록이 있는 방향 버튼을 누르면 한 칸 올라감(에너지 -1).
- 반대 방향을 누르면 헛디뎌 하트 -1(제자리 유지). 하트 0이면 종료. 시간 제한 없음.
- 점수 = 오른 계단 수.

### 기록 화면
- 게임 종료 시: 이번 기록, 최고 기록, 신기록 여부, "다시 하기/메뉴로".
- 최고 기록은 게임별 localStorage 저장.

### 문제 데이터
- 파일: `data/questions/<세트>.json`, 목록은 `data/questions/index.json`.
- 세트 형식(고정): `{ id, title, subject, grade, units:[{id,title}], items:[{unit, q, answer, distractors?}] }`
- 구구단은 데이터 파일 대신 생성기(`gugudan`)로 만들고 단(2~9단, 복수 선택·전체)을 선택. 형식은 위 세트와 같은 출력.
- 선택 화면: 과목 → 세트 → 단원(칩 복수 선택) → 게임 선택.
- 영단어·분수는 샘플 몇 개만 넣어 형식이 통하는지 확인하고, 실제 문제는 사용자가 추후 제공.

## 6. 구조와 에이전트 분업
```
index.html
css/            (ui 담당)
js/core/        (뼈대: 소넷이 먼저 직접 작성) main, router, energy, quiz-engine, storage, input, audio
js/games/jump/      (소넷 에이전트 1)
js/games/stairs/    (소넷 에이전트 2)
js/ui/              (소넷 에이전트 3: 메뉴·문제 선택·퀴즈 화면·결과 화면)
data/questions/     (하이쿠 에이전트: 구구단 생성기, 샘플 세트)
```
- 게임 인터페이스: `init(ctx) / start() / update(dt) / render() / destroy()`. ctx는 캔버스, 입력, 에너지(`spend(n)`), 하트, `openQuiz()`, `endGame(score)`를 제공.
- 1단계(뼈대): 소넷이 인터페이스·에너지·퀴즈 엔진·데이터 형식을 확정하고 순수 로직 테스트(node)로 검증.
- 2단계(병렬): 위 4개 에이전트가 각자 자기 폴더만 수정. 서로의 폴더는 읽기만.
- 3단계(검수): 더 강한 모델이 브라우저(모바일 크기)에서 두 게임과 퀴즈를 직접 플레이해 버그와 수치를 확인하고 수정 요청.

## 7. 검증
- 로직(에너지, 배율, 보기 생성, 구구단 생성)은 node 스크립트로 테스트.
- 화면과 조작은 브라우저 모바일 크기(375×812)에서 직접 확인.

## 8. 빌더에게 맡기는 부분
- 점프 높이, 중력, 이동 속도, 발판 간격 곡선 등 수치 튜닝(초등학생이 즐겁게 할 난이도)
- 색상 팔레트, 폰트, 효과음의 구체 모양, 애니메이션
- 빌딩 외벽·블록·캐릭터의 그래픽(단순 도형/CSS/Canvas로 구현, 외부 이미지 불필요)
- 위에 적지 않은 사소한 UI 문구는 한국어로 쉽고 짧게

## 9. 제 판단으로 정한 것 (확인 필요)
- 무한의 계단의 좌/우 버튼 = 방향 맞춰 한 칸씩 오르기, 틀리면 하트 -1 (원작은 즉시 종료이나 하트 규칙과 통일)
- 에너지 최대 10, 연속 정답 배율 값, 오답 힌트(연속 2번 시 보기 1개 제거)
- 하트 3개, 무적 시간 1.5초
- 점프맵 낙하 시 마지막 안전 발판에서 부활

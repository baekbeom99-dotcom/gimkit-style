작성일: 2026-11-26 / 상태: 설계 승인 완료 · 문서 검토 대기  
기준 문서: `2026-11-19-gimkit-energy-game-design.md` (에너지·퀴즈·기록·모바일 세로 화면 규칙)

## 1. 의도
플레이어가 *탭 타이탄즈 1·2*의 호쾌한 연타·성장·보스 공략 감각과 *아이언 스나우트(Iron Snout)*의 좌우 아레나 웨이브·스테이지 테마 감각을 한 게임 안에서 함께 즐길 수 있도록 한다.  
더불어 본 앱의 학습 정체성을 두 가지 선택지로 제공한다:
- **탭 모드**: 원작처럼 직접 연타하는 손맛 중심 + 스테이지별 에너지 충전 퀴즈 루프 유지
- **문제풀이 모드**: 탭 연타 대신 화면 하단에 **항상 문제 영역을 고정 배치**해, 문제를 맞힐 때마다 캐릭터가 적을 공격하는 학습 집중형 플레이

## 2. 목표 / 비목표 / 안티목표

**목표**
- 새 게임 1종 추가 (`id: 'titans'`, 시작 화면 6번째 타일, 픽셀 아이콘 포함)
- 시작 시 **탭 모드** / **문제풀이 모드** 2가지 플레이 방식 선택 (`ctx.choose`)
- 매 스테이지 내부를 **좌우 웨이브(아이언 스나우트) → 1:1 거대 보스전(탭 타이탄즈)** 2페이즈로 교차 구성하고, 스테이지마다 6종 바이옴 배경/적을 순환 적용
- 골드 획득 → **⚔ 검 강화(클릭/문제 공격력)** 및 **🛡 동료 강화(자동 DPS)** 핵심 RPG 성장 루프 구현
- 문제풀이 모드에서 기존 `quiz-screen.js`의 모든 과목·유형(구구단, 덧셈·뺄셈, 분수 SVG 도형, 영단어+TTS, 일본어 히라가나·가타카나)을 하단 영역에서 100% 그대로 출제

**비목표**
- 프레스티지(환생)·유물·장비 가챠·스킬 트리 같은 장기 방치형 메타 시스템 및 영구 RPG 세이브
- 외부 에셋/스프라이트 시트 의존, 멀티플레이/온라인 랭킹
- 기존 5개 게임(`jump`, `stairs`, `tower2d`, `stack3d`, `obby`)의 레이아웃이나 규칙 변경

**안티목표**
- 탭 모드에서 1탭마다 에너지를 깎아 1~2초마다 퀴즈 팝업으로 연타 흐름을 끊는 설계
- 문제풀이 모드에서 하단 문제 버튼과 상단 캔버스가 겹치거나, 보스전 중 팝업이 갑자기 떠서 선택지 입력을 방해하는 현상
- 빈 화면 전환으로 어떤 페이즈(좌우 웨이브 vs 보스전)인지 헷갈리는 UX

## 3. 아키텍처 (방식 A: DOM + Canvas 하이브리드)

### 3.1 `#dock` 하단 슬롯 및 `ctx` 확장
`index.html`의 `#app` 세로 기둥(`display: flex; flex-direction: column`)을 아래와 같이 확장한다.

```html
<div id="app">
  <div id="hud"></div>
  <div id="stage">
    <canvas id="game" width="360" height="640"></canvas>
    <div id="controls"></div>
  </div>
  <div id="dock" hidden></div>
  <div id="screen"></div>
</div>
```

- `#dock`는 평소 `hidden` 상태(`display: none`)이므로 기존 5개 게임은 `#hud` + `#stage` 구도를 100% 그대로 유지한다.
- `js/main.js`는 `startGame` 시 `ctx`에 다음 인터페이스를 추가 제공한다:
  - `ctx.dock`: `#dock` DOM 컨테이너 (`hidden` 해제·초기화는 `teardown()`이 자동 정리)
  - `ctx.session`: 현재 선택된 과목/단원의 퀴즈 세션(`createQuizSession` 인스턴스)
  - `ctx.resizeStage(logicalH)`: `#dock` 높이에 맞춰 `<canvas>` 논리 높이를 조정하는 헬퍼(문제풀이 모드에서는 상단 전투 캔버스를 약 `240~280` 논리 높이에 맞춰 찌그러짐 방지)
  - `ctx.hud`: 기존 `setScore` 외에 `setChargeEnabled(bool)`를 선택적으로 지원해 문제풀이 모드 중 상단 `⚡+` 수동 충전 버튼을 숨김/비활성 처리
- `js/core/input.js`는 `'arena'` 레이아웃을 추가해 화면 왼쪽 절반 터치를 `'left'`, 오른쪽 절반 터치를 `'right'` 이벤트로 방출한다(데스크톱 키보드 `◀`/`▶`/`A`/`D`와 동일 이벤트로 통합).

### 3.2 공용 인라인 위젯 `quiz-panel.js` 분리
기존 `js/ui/quiz-screen.js`의 문제 출제·렌더링·정답 판정 로직을 재사용 가능한 위젯으로 분리한다.

- **`js/ui/quiz-panel.js`** (`mountQuizPanel(container, { session, mode, onAnswer, onSpeak, sfx })`):
  - `word`(영단어 + `🔊` 다시 듣기 + `q.prompt`), `figure`(분수 SVG `renderFigure`), `equation`(`47 + 8 = ?`) 3가지 문제 유형을 동일하게 렌더링한다.
  - 4지선다 버튼(`.ui-quiz-choices`) 클릭 시 즉시 `locked = true`로 중복 터치를 막고 `session.answer(i)` 결과를 `onAnswer(result, question)` 콜백으로 전달한다.
  - 오답 시 `SHOW_CORRECT_MS` 또는 `lockMs` 동안 정답을 하이라이트한 뒤 자동으로 다음 문제를 출제한다.
  - 반환 객체 `{ next(), destroy() }`로 생명주기와 TTS(`cancelSpeech()`)를 깔끔하게 정리한다.
- **`js/ui/quiz-screen.js`**:
  - 상단 게이지·연속 정답 배지·닫기(`✕`)·에너지 충전 완료 종료(`finish`)만 래핑하고, 내부 문제/선택지 영역은 `mountQuizPanel`에 위임해 중복 코드를 제거한다.

## 4. 게임 모드 및 조작 규칙

게임 시작 시 `ctx.choose`로 모드를 고른다.

| 항목 | 👆 탭 모드 (`tap`) | 📝 문제풀이 모드 (`quiz`) |
|---|---|---|
| 공격 트리거 | 화면 탭(연타) | 하단 `quiz-panel` 문제 정답 |
| 웨이브(좌우 적) 조작 | 왼쪽 절반(`◀`/`A`) → 왼쪽 공격<br>오른쪽 절반(`▶`/`D`) → 오른쪽 공격 | 정답 시 **가장 가까운(위협적인) 적 자동 추격 타격** + 양옆 적 넉백 |
| 보스(1:1) 조작 | 화면 아무 곳이나 탭(`Space`/`◀`/`▶` 포함) | 정답 시 **강력한 일격**(검 공격력 × 문제 보너스 × 연속 정답 배수) |
| 오답 / 헛스윙 페널티 | 적이 없는 빈 방향 탭 시 `0.16s` 경직(쿨다운) | `0.9s` 입력 잠금 + 적 접근 가속(웨이브) / 보스 반격 위협 |
| 하단 `#dock` 구성 | 콤팩트 RPG 바 (`골드` · `⚔ 검 강화` · `🛡 동료 강화`) | 상단 미니 강화 바 + **상시 퀴즈 영역(`quiz-panel`)** |
| 상단 `#stage` 비중 | 전체 높이의 ~78% | 전체 높이의 ~44~48% |

## 5. 스테이지 교차 및 바이옴 순환 규칙

### 5.1 스테이지 내부 2페이즈 교차
모든 스테이지 `N` (`1, 2, 3, ...`)은 다음 두 페이즈를 순서대로 거친다.

1. **페이즈 1: 좌우 웨이브 (아이언 스나우트 스타일)**
   - 주인공이 아레나 중앙(`x = 0.5`)에 서고, 좌(`x = 0`)와 우(`x = 1`) 양 끝에서 일반 몬스터들이 다가온다.
   - 스폰 수: `waveTarget = 4 + Math.min(8, Math.floor(stage / 2))`마리.
   - 좌·우 교차 및 동시 접근 패턴(초반은 1마리씩 번갈아, 스테이지 상승에 따라 양쪽 동시 출현 확률 증가)으로 긴장감을 준다.
   - **탭 모드 접근 속도**: 기본 이동 시간 약 `2.8s ~ 1.7s` (스테이지 완만 스케일링). 방향을 맞춰 타격하면 즉시 넉백 + 데미지, HP가 0이 되면 처치된다.
   - **문제풀이 모드 접근 속도**: 문제를 읽고 푸는 시간을 보장하기 위해 탭 모드 대비 약 `0.45배` 속도로 접근하며, 정답 시 타격 대상 처치/넉백 + 반대편 근접 적도 소폭 밀려난다(`0.25` 거리 넉백). 오답 시 접근 중인 적들이 한 걸음(`0.18` 거리) 전진한다.
   - 적이 주인공 피격 거리(`|x - 0.5| <= 0.08`)에 도달하면 주인공이 피격(**하트 -1**, 전체 적 넉백, `0.8s` 짧은 무적)된다.

2. **페이즈 2: 거대 보스전 (탭 타이탄즈 1·2 스타일)**
   - 웨이브 남은 수가 `0`이 되면 화면에 `"⚠ BOSS BATTLE"` 배너가 뜨고, 아레나 우측 중앙에 거대 타이탄 보스가 착지한다(주인공은 좌측 전방으로 자리 이동).
   - **제한 시간**: 탭 모드 `30.0초`, 문제풀이 모드 `45.0초`.
   - 제한 시간 안에 보스 HP를 `0`으로 만들면 스테이지 클리어 → 금화 대량 드롭 → 다음 스테이지/바이옴으로 전환된다.
   - **시간 초과 시**: 보스가 밀어내기 공격을 가해 **하트 -1**이 깎이고, 보스의 **남은 HP는 유지된 채** 보스전 타이머가 초기화되어 즉시 재도전한다(하트가 0이 되면 게임 오버).

### 5.2 6종 바이옴 순환 (아이언 스나우트 + 탭 타이탄즈 교차)
스테이지 `1, 2, 3, 4, 5, 6`마다 아래 바이옴이 순서대로 순환(`(stage - 1) % 6`)하며, 배경 팔레트·바닥 플랫폼·원경 소품·일반 적·보스 실루엣이 모두 바뀐다.

| 순번 | 바이옴 | 레퍼런스 | 배경 · 아레나 연출 | 일반 적 / 보스 |
|---|---|---|---|---|
| 1 | 🌲 초록 숲 | 아이언 스나우트 (Forest) | 낮 하늘, 겹겹이 우거진 침엽수, 잔디 바닥 | 숲 들늑대 / 고대 숲 거인 |
| 2 | 🏙 네온 거리 | 아이언 스나우트 (City) | 노을~야경 빌딩 실루엣, 가로등, 아스팔트 | 철퇴·로켓 늑대 / 메카 울프 |
| 3 | 🏴‍☠️ 해적선 갑판 | 아이언 스나우트 (Pirate Ship) | 파도·돛대·나무 난간, 흔들리는 갑판 바닥 | 해적 늑대 / 크라켄 선장 |
| 4 | 🪨 고대 유적 | 탭 타이탄즈 (Ruins) | 부서진 신전 기둥, 덩굴, 석판 바닥 | 스톤 임프 / 유적 골렘 |
| 5 | 🌋 용암 성채 | 탭 타이탄즈 (Lava) | 붉은 하늘, 용암 폭포와 불씨 파티클, 흑요석 바닥 | 파이어 슬라임 / 화염 타이탄 |
| 6 | ❄ 만년 설산 | 탭 타이탄즈 (Frost) | 오로라, 설산 봉우리, 눈 내리는 얼음 바닥 | 서리 야수 / 아이스 타이탄 |

## 6. RPG 성장 · 에너지 · 밸런스 수치 (시작값)

모든 수치는 `js/games/titans/logic.js` 상단에 상수로 모아 추후 브라우저 테스트 결과에 따라 손쉽게 조정한다.

### 6.1 전투 및 스케일링 공식
- **기본 공격력 (검 Lv. `L`)**:
  - 탭 모드 1탭 피해: `tapDmg = Math.round(5 * Math.pow(1.22, L - 1))`
  - 문제풀이 모드 1정답 피해: `quizDmg = Math.round(tapDmg * 8 * streakMult)`
    - 연속 정답 배수 `streakMult`: `1연속 = 1.0`, `2연속 = 1.25`, `3~4연속 = 1.5`, `5연속+ = 2.0`
  - 치명타: 검 `Lv.3`부터 해금, 기본 `12%` 확률(최대 `30%`)로 `2.0배` 피해 + 황금 `CRITICAL!` 숫자 팝업
- **동료 자동 공격 (동료 Lv. `A`)**:
  - `A === 0`이면 미고용(`DPS = 0`). `A >= 1`이면 `dps = Math.round(4 * Math.pow(1.26, A - 1))`
  - 화면 연출: `Lv.1` 궁수(원거리 화살), `Lv.5` 마법사(마법탄), `Lv.10` 기사(돌진 보조)가 최대 3명까지 주인공 뒤에 합류해 시각적으로 함께 싸운다.
  - 웨이브 페이즈에서는 동료가 `1.4초`마다 가장 가까운 적에게 지원 타격을 가해 웨이브 부담을 덜어 준다.
- **적 HP 및 골드 보상**:
  - 일반 적 HP: `mobHp = Math.round(12 * Math.pow(1.28, stage - 1))`
  - 보스 HP: `bossHp = Math.round(mobHp * 11)` (탭 모드) / `Math.round(mobHp * 6.5)` (문제풀이 모드 — 분당 풀 수 있는 문제 수 기준 보정)
  - 처치 골드: 일반 적 `Math.round(4 * Math.pow(1.22, stage - 1))`, 보스 `mobGold * 6`
- **강화 비용**:
  - 검 강화 비용: `Math.round(10 * Math.pow(1.32, swordLv - 1))`
  - 동료 강화 비용: `Math.round(18 * Math.pow(1.36, allyLv))`

### 6.2 에너지(`energy`) 및 하트(`hearts`) 통합
- **탭 모드**:
  - `energyMax = 10`으로 시작(가득 참).
  - 연타 도중 퀴즈가 끼어들지 않도록 **스테이지를 클리어해 다음 스테이지로 넘어갈 때만 에너지 `⚡ 1`을 소모**한다.
  - 에너지가 `0`이 되면 다음 스테이지 시작 직전 `ctx.requestQuiz({ mode: 'refill' })`가 자동으로 열려 문제를 풀고 재개한다. (상단 HUD의 `⚡+` 미리 충전도 언제든 사용 가능)
- **문제풀이 모드**:
  - 하단 `quiz-panel`이 상시 에너지 공급원 역할을 하므로 **에너지 고갈 팝업은 띄우지 않는다**(`requestQuiz` 미호출).
  - 대신 정답마다 `energy.add(r.gain)`으로 상단 에너지 게이지를 채우고, 게이지가 가득(`10/10`) 차면 **`⚡ OVERDRIVE` 발동**(에너지를 0으로 비우며 즉시 **화면 전체 적에게 `quizDmg × 2.5` 번개 일격 + 5초간 공격력 1.5배 버프**).
  - HUD에서 `⚡+` 버튼은 문제풀이 모드 중 불필요하므로 비활성화 또는 숨김 처리한다.
- **하트(`❤ × 3`) 및 게임 종료**:
  - 피격(웨이브 충돌 또는 보스 타임아웃) 시 `hearts.lose()`.
  - `hearts.value === 0`이 되면 즉시 `ctx.endGame(stage)`를 호출해 결과 화면에 도달 스테이지(`score = stage`)와 최고 기록을 저장·표시한다.

## 7. 화면 배치 및 모바일 대응

- **세로 기준 논리 폭 `360px`**:
  - **탭 모드**: 상단 `#hud` → `#stage`(`360 × ~480` 비율, 좌/우 반분할 터치 영역 표시) → `#dock`(단일 행 골드·검·동료 강화 바 `~76px`).
  - **문제풀이 모드**: 상단 `#hud` → `#stage`(`360 × ~240` 전투 캔버스) → `#dock`(미니 강화 바 `~48px` + `quiz-panel` 문제 카드 및 2×2 보기 버튼).
- **낮은 화면(`max-height: 700px`) 대응**:
  - CSS 미디어쿼리로 문제풀이 모드의 캔버스 최대 높이, `.ui-quiz-q` 최소 높이(`72px`), 보기 버튼(`min-height: 58px`)을 자동 축소해 모바일 브라우저 주소창이 떠도 스크롤 없이 한 화면에 조작 가능하게 한다.
- **가로 휴대폰**: 기존 `main.js`의 `rotate-overlay`("화면을 세로로 돌려 주세요")가 그대로 동작한다.

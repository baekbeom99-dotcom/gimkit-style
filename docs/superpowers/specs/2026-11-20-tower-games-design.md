# 탑쌓기 게임 2종 — 설계 문서 (3D 스택 / 2D 트리키 타워)

작성일: 2026-11-20 / 상태: 승인 대기
기준 문서: `2026-11-19-gimkit-energy-game-design.md` (에너지·퀴즈·하트·기록·모바일 세로·전체 화면 규칙을 그대로 따른다)

## 1. 의도
기존 점프맵, 무한의 계단에 이어 "탑쌓기" 게임 2종을 추가한다. 둘 다 에너지가 닳고, 0이 되면 퀴즈로 충전하는 기존 구조 안에서 동작한다.

레퍼런스 확인 결과 (불확실한 부분 포함):
- 3D 탑쌓기: 네이버 블로그는 접근이 막혀 읽지 못했다. 사용자가 준 유튜브 영상은 제목 "[STACK 스택] 탑 쌓기 게임 … 구글플레이"만 확인했다(35초 장면은 확인 못 함). 티스토리 글(from2015.tistory.com/629)은 읽혔고 스택 방식임을 확인했다. 그래서 케첩 스택 방식으로 이해했다.
- 2D 탑쌓기: 유튜브 "200 IQ Strats In Tricky Towers"의 제목만 확인했다. 트리키 타워 방식으로 이해했다(1인용).
- 두 게임 모두 규칙의 세부(수치, 연출)는 아래 내용이 "제 판단"이며, 영상 내용을 보고 확정한 것이 아니다.

## 2. 목표 / 비목표 / 안티목표
**목표**: 두 게임 추가, 시작 화면 타일 2개 추가(총 4개, 2열), 전체 화면 모바일 세로, 에너지/퀴즈/하트/기록 연동, 픽셀 아이콘.
**비목표**: 멀티플레이, 트리키 타워의 마법 요소, WebGL/three.js, 서버/랭킹.
**안티목표**: 퀴즈가 탑 쌓는 중간에 끼어들어 흐름이 끊김(퀴즈는 항상 블록이 안착한 뒤에만 연다), 블록이 물리 오류로 뚫고 지나가거나 이유 없이 무너짐.

## 3. 접근 방식
- 3D 탑쌓기: (선택) 캔버스로 직접 그리는 아이소메트릭. 원본 스택이 원근감 없는 고정 시점이라 거의 동일하게 재현되고 내려받을 파일이 없다. (대안 three.js ≈600KB는 사용자가 답하지 않아 제외, 문서 확인 때 바꿀 수 있음)
- 2D 탑쌓기: matter.js 0.19.0을 `js/vendor/matter.min.js`로 내려받아 사용(사용자가 허락함: cdn.jsdelivr.net, 약 80KB). 직접 물리 구현은 안정성 위험이 커서 제외.

## 4. 공통 통합
- `js/games/registry.js`에 `stack3d`(3D 탑쌓기), `tower2d`(2D 탑쌓기) 추가. 게임 모듈 규칙은 기존과 동일(`create(ctx)`, `fullscreen: true`, `energyMax`, `energyGainMultiplier`).
- 기록은 `recordScore`(게임 id별 최고 기록), 결과 화면 재사용. 기록 박스는 우측 상단 HUD 버튼 아래에 고정 크기(CSS 픽셀 기준)로 그린다(기존 점프맵/계단과 같은 방식).
- 입력 확장(`js/core/input.js`): 레이아웃 `tap`(화면 전체 탭 → `jump` 이벤트), 레이아웃 `tower`(왼쪽 절반 다이나믹 조이스틱 = 좌우 + 아래 당기기 `held.down`, 오른쪽 절반 탭 = 회전 → `jump` 이벤트). 기존 레이아웃은 그대로.
- 시작 화면: 픽셀 아이콘 2종 추가, 타일은 2열이라 2행(스크롤 가능).
- 에너지 규칙: 블록(또는 벽돌) 하나를 쓸 때 -1. 에너지가 0이면 해당 블록이 안착한 직후 퀴즈가 열리고, 퀴즈가 끝나면 다음 블록이 나온다.

## 5. 3D 탑쌓기 (stack3d) 규칙
- 시작: 바닥 블록(가로·세로 200, 높이 28). 이후 층마다 블록이 x축, z축을 번갈아 왕복한다. 속도 `v = 140 + 6 * 층수`(상한 420), 화면 아무 곳이나 탭하면 놓인다.
- 놓을 때: 아래 층과 겹친 부분만 남고 튀어나온 부분은 잘려 떨어진다(회전 없이 떨어지며 사라짐). 오차 4 이내는 퍼펙트(정확히 맞춤, 크기 유지, 소리/효과). 퍼펙트 연속 3회부터 블록이 한 번에 +6씩 회복된다(최대 처음 크기).
- 완전히 빗나가면(겹침 0) 하트 -1, 그 층은 다시 시도(블록 크기 유지). 하트 0이면 종료.
- 점수 = 쌓은 층수. 에너지 최대 20, 정답 충전 ×2. 색은 파스텔톤으로 층마다 색상이 12°씩 바뀌고 배경도 천천히 변한다. 카메라는 위 층을 따라 올라간다.
- 퍼펙트 효과음: 연속 퍼펙트마다 도레미파솔라시도 순으로 음이 올라간다(8음 순환, 퍼펙트가 끊기면 처음 음으로). 기존 효과음 목록에 없어 `js/core/audio.js`에 음높이를 받는 효과음(`note`)을 추가한다.
- 근거(블로그 "와이파이 필요없는 게임, 스택"에서 확인된 내용): 앞면 가장자리에 맞춰 놓는 방식, 실수할수록 탑이 좁아져 난이도가 오르는 구조, 퍼펙트 시 올라가는 음계, 파스텔 블록. 점수 표시와 카메라 등 나머지는 확인하지 못해 제 판단이다.
- 논리는 `js/games/stack3d/logic.js`(순수 함수)로 분리하고 단위 테스트한다.

## 6. 2D 탑쌓기 (tower2d) 규칙
- 세계: 가로 360, 아래쪽 좁은 받침대(폭 150, 두께 14) 아래는 낭떠러지. 벽돌은 7종 테트로미노(I O T S Z J L), 한 칸 24px, 7개 묶음에서 섞어 뽑는다(같은 모양이 연속 3번 나오지 않음).
- 조작: 벽돌이 천천히 내려오는 동안 좌우 이동(최대 180px/s), 아래로 당기면 빠르게(360px/s), 오른쪽 탭으로 90° 회전. 벽돌이 다른 벽돌이나 받침대에 닿으면 조종이 끝나고 물리에 맡긴다. 안착(속도가 충분히 작아진 뒤 0.6초)하면 다음 벽돌이 나온다.
- 하트: 받침대 밖으로 벽돌이 떨어지면 하트 -1(벽돌당 한 번). 하트 0이면 종료.
- 점수 = 안착한 벽돌 중 가장 높은 지점의 높이(m, 40px = 1m). 에너지 최대 12, 정답 충전 ×2. 낙하 속도는 벽돌 수가 늘수록 조금씩 빨라진다.
- 물리: 마찰 0.9, 반발 0, 고정 시간 간격 1/60초에 2번 하위 단계, 위치/속도 반복 10/8. 카메라는 탑이 화면 위쪽 40%를 넘으면 따라 올라간다.
- 순수 논리(`tower-logic.js`: 모양 정의, 회전, 7개 묶음 추첨, 높이/낙하 판정)는 단위 테스트하고, 물리 안정성은 node에서 matter를 돌리는 테스트로 확인한다(예: O 벽돌 6개를 정렬해 쌓고 5초 시뮬레이션해도 낙하 0).

## 6-A. 2D 탑쌓기 갱신: Tricky Towers 조사 반영 (이 절이 6절과 다르면 이 절이 우선)
조사 출처(리뷰·위키 수준, 세부 수치는 확인 못 함): Wikipedia, Giant Bomb, Steam 커뮤니티 설명. 확인된 것: 모드는 레이스(결승선 높이까지 쌓기)·서바이벌(정해진 벽돌 수를 목숨 3개로 쌓기)·퍼즐, 밝은 마법(단단한 벽돌, 덩굴로 연결, 마지막 벽돌 제거)과 어두운 마법(얼음, 거대 벽돌, 풍선), 실제 물리 적용, 섬세한 조작.
이를 1인용으로 줄여 아래와 같이 정한다(수치는 제 판단).
- **레이스+서바이벌 방식**: 받침대 위로 일정 간격(6m = 240px)마다 결승선이 있다. 탑의 안착한 꼭대기가 결승선을 넘고 2초간 유지되면 "스테이지 클리어": 하트 +1(최대 3), 낙하 속도 +10%, 다음 결승선이 6m 위로 이동, 마법 벽돌 1개 보장. 점수 = 최고 높이(m).
- **하트 3개**: 받침대 밖으로 벽돌이 떨어지면(벽돌당 한 번) 하트 -1.
- **밝은 마법 벽돌(약 5개마다 1개, 테두리가 빛남)**: 놓은 뒤 효과가 발동 — ① 단단: 밀도 4배·마찰 최대, ② 덩굴: 닿아 있는 벽돌과 제약(Constraint)으로 연결, ③ 되돌리기: 마지막으로 놓은 벽돌 제거(하트는 깎이지 않음). 종류는 무작위.
- **어두운 마법(스테이지 3부터 약 8개마다 1개, 검게 빛남)**: ① 얼음: 마찰 0, ② 거대: 1.5배 크기. 어두운 마법은 내가 내려야 하는 벽돌에 걸린다(싱글 서바이벌의 웨이브 느낌).
- **조작**: 왼쪽 절반 드래그 = 좌우 이동(아래로 끌면 빠르게 낙하), 오른쪽 절반 탭 = 회전. 섬세한 조작을 위해 이동은 속도 제한과 가벼운 가속을 둔다.
- 에너지는 벽돌 하나를 쓸 때 -1(최대 12, 정답 충전 ×2), 0이면 벽돌이 안착한 뒤 퀴즈. 퀴즈 중에는 물리를 멈춘다.
- 어두운 마법의 풍선, 상대 방해, 다인 대전은 이번 범위 밖.

## 7. 제약
기존 문서의 제약을 따른다(빌드 도구 없음, ES modules, 외부 음원 없음, 세로 화면). 추가로 `js/vendor/matter.min.js`만 허용한다.

## 8. 빌더에게 맡기는 부분
색상 팔레트, 효과음 조합(기존 sfx 이름만 사용), 연출(잘린 조각 낙하, 먼지), 수치 미세 조정, 아이콘 모양.
